# Tessera: build plan (real data only)

Source brief: "Web - Project Management APP.pdf" (a Jira-style bug/issue tracker on the MERN stack: goal, tech stack, 10 use cases, 14-day schedule, deliverables).

**Tessera** is Latin for a single mosaic tile. Every ticket is a tile, and the board is the finished picture.

## Ground rules (same as Hopin and Spendwise; re-read before every step)

1. **Nothing simulated.** No demo workspaces, no fake seed tickets, no charts filled with made-up numbers. A new user starts with zero projects, and every view shows an honest empty state until real data exists. If a feature is missing its key (for example, email invites without SMTP or the GitHub webhook without its secret), the API says it isn't configured and the UI shows that.
2. **No fake text in the app** to make something look finished.
3. **One step at a time.** Each step is: build → test against the real service → report what was verified → wait for your go-ahead.
4. **Keys are requested before the step that needs them.** You create the accounts.
5. **Backend, database and APIs first**, then the frontend.
6. **Free tiers only.** Anything paid gets flagged before it is used.

## Decided (2026-11-05)

- Name: **Tessera**. Folder `my-dashboard/tessera`, its own git repo (branch `main`).
- Database: **MongoDB Atlas**, your existing free Cluster0 with a new database `tessera` (no new account).
- Our own JWT auth (bcrypt), as the brief asks.
- Scope: every item in the brief's schedule and use cases (including the optional ones: roles and screenshot uploads), **plus** four signature feature groups that Jira and Asana either lack or keep behind paid plans (below).
- Local ports: API **8740**, client **5210** (Vite proxies `/api` and the Socket.IO connection to the API in dev).

## Do we need datasets?

**No.** A tracker's data is the team's own projects and tickets. Tests run against a throwaway MongoDB (mongodb-memory-server), never the real database.

## Signature features (beyond Jira / Asana)

| Group | What it does |
| --- | --- |
| **Bug intelligence** | Paste a stack trace or console error and it becomes a structured ticket (error type, message, top frames, file and line, browser/OS). A **duplicate warning while typing** the title, using local text similarity (TF-IDF over the project's tickets; no paid AI). An **in-browser screenshot annotator**: arrows, boxes, and blur for secrets before anything is uploaded. Errors with the same fingerprint are grouped. |
| **Flow analytics** | Every status change is stored as an event, so we get real **cycle time**, **time in each status**, **WIP limits** per column, a **cumulative flow diagram**, **stale ticket** detection, and **board time travel**: see the board exactly as it was on any past date. |
| **Live collaboration** | Socket.IO live board (a card moves on everyone's screen), **presence** (who is looking at a ticket), **typing indicators** in comments, **@mentions**, in-app + email notifications, and a **workload heatmap** that warns before you assign someone who is already overloaded. |
| **Outside-in workflow** | A **public bug-report portal** per project (a link clients can use without an account; reports land in a triage inbox, rate-limited), a **GitHub webhook** so a commit or PR saying `fixes TES-12` links and closes the ticket, and a **release-notes generator** that turns finished tickets into a Markdown changelog. |
